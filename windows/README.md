# Windows 10 兼容性检查与服务骨架

## 先在一台测试机检查

`ohno-check.cmd` 是只读检查，运行不需要 .NET，也不主动请求管理员权限。它查询系统版本、架构、BFE/防火墙等服务和常见系统工具，不会更改系统设置。请从资源管理器双击运行并提供窗口输出。它不能证明所有 WFP 接口可用、网络驱动兼容或后续安装一定成功。`where` 不可用时检查结果可能不准确。出于隐私，它不主动读取账号名、IP 或个人文件。

## 服务骨架

`service.cpp` 是原生 Win32 单服务的生命周期骨架：接收 SCM 启动、停止和关机消息。目前支持向教师端注册和轮询规则，仅有按文件名或哈希定期扫描并尝试终止进程的试验性拦截（并非启动前拦截），支持可选 4–8 位课堂 PIN 的临时解锁；安装和服务崩溃恢复仍为试验性实现，也不能作为成品部署。

构建命令与顺序以 [Windows CI 工作流](../.github/workflows/prototype.yml) 为准：先构建固定 SCM 宿主、worker、请求界面和纯维护载荷，再用 `teacher/update_package.py` 生成初始固定格式包，最后将包与固定请求启动器嵌入单文件安装器。构建机需要 Python；学生机运行时不需要 Python、.NET 或额外 VC++ 组件。

构建需要编译器及 SDK，成品运行时按 `/MT` 静态链接 C/C++ 运行库，不需要另装 .NET 或 Visual C++ 再发行包。精简系统可能缺失 Windows 自身的基础组件，必须通过实机检查和测试。

安装器仅供隔离环境试验，不能用于真实教室镜像。

服务从注册表 `HKLM\SOFTWARE\Ohno` 的字符串值 `ServerUrl` 读取教师端 HTTPS 根地址，使用系统证书信任链；设备凭据在本机系统注册表生成，教师批准后开始轮询。原型使用物理网卡永久 MAC（优先有线）、SMBIOS UUID 共同锚定设备凭据，IP 地址变化不影响身份。若原系统不报告物理 MAC，则退回支持的网卡当前地址，若完全无法识别 MAC 则终端暂不注册，等待检测到可用网卡。主硬件锚变化时重建设备凭据并请求教师重新审批；没有 UUID 且没有可用 MAC 时拒绝注册。尚未验证兆芯机器的 UUID 是否存在且唯一，因此仍不能用于实际镜像分发。

进程检测存在启动后至扫描前的时间窗口，拒绝执行可能失败，不能作为恶意程序防护。网站规则通过 TUN 按可识别的域名拦截，并通过 Edge 的 URLBlocklist 补充；加密或无法识别的域名及排除的内网网段不保证覆盖。不会显示自定义提示；网站申请需要通过桌面快捷方式手动发起。来源联网限制仅有不完整的试验性实现。教师可选择对 Edge 尝试限制所有本地文件；它可能影响 PDF 和课件，且无法保证覆盖全部本地 HTML。

## 一键安装

教师电脑双击 `ohno-teacher.exe` 并在管理页面下载学校专属 `Ohno-School-Setup.exe`。当前源码构建的学生机单文件安装包双击后允许 UAC，再输入教师端预先设置的维护密码；原生安装器会读取内嵌的服务器 HTTPS 地址和**公开证书**，先在线验证教师身份与授权，再安装并启动 Windows 服务。镜像分发后不重复输入。已发布 alpha.6 旧安装器没有这项密码保护。不需要 `.NET`、VC++ 再发行组件或者命令行。教师在 Web 管理端批准设备后才会下发策略。

公版 `ohno-setup.exe` 同样支持双击，显示地址与证书浏览的 Win32 安装窗口；学校专属安装包无需输入地址或证书路径。受信任根证书存储是整机范围的敏感设置，须由 IT 核实教师服务器和证书。仍有服务权限、证书信任及联想镜像分发待兆芯实机测试。

## 安装器试验代码

`setup.cpp` 和 `setup.rc` 可将服务嵌入一个原生安装程序。实验参数：`ohno-setup.exe --install https://teacher.example:8443 --certificate cert.pem`（自签证书）或省略 `--certificate`（证书已受信任）；移除：`ohno-setup.exe --remove`。安装与正常卸载都会显示原生教师维护密码框，要求在线授权；Windows 应用列表也提供同一卸载入口。程序要求管理员权限、创建自动启动服务并设置有限的 SCM 崩溃重启。指定 `--certificate` 会把所提供的自签证书加入计算机根证书存储，影响全系统的信任范围；只应在学校 IT 核验证书后使用。卸载时只移除由安装器新增的证书。当前只适用于构建与隔离测试，尚未验证完整卸载、镜像分发和学校实际环境。

策略在成功下载后缓存在受限注册表中；服务器离线时尝试继续执行缓存规则，但不沿用临时放行。若设备身份因硬件变化重建，会先清除本程序记录的 Edge 规则和缓存。断网期间的游戏申请只暂存在内存，重启服务后可能丢失。该机制尚需完整集成测试。

程序联网限制有实验性实现：周期性检查运行中的可执行文件，识别 NTFS 下载区域标记或当前可移动磁盘路径，并在 WFP 对该程序添加 IPv4/IPv6 出站连接阻断规则；教师可对哈希临时放行。**这不是可靠的防病毒功能**：扫描前已有连接可能发生；来源标记可以丢失；U 盘文件复制后可能失去来源；脚本/共享运行时及代理进程的联网不能可靠归属；服务停止时动态规则消失。仅供受控测试。

安装器会创建“ohno website request”公共桌面快捷方式。学生输入域名后，本机服务向教师端提交网站申请；教师批准后试验性地通过 Edge URLAllowlist 对该设备精确放行，过期或离线后移除。请求与放行目前只覆盖 Edge；服务重启时未同步的请求会丢失。

教师可通过学生机窗口输入可选的 4–8 位课堂 PIN，暂时解除本机 ohno 限制一小时；PIN 默认关闭，并与教师后台权限无关。学生拥有管理员权限时仍可能读取输入，因此应优先在教师机本地管理页审批。

TUN 使用随安装包携带的 sing-box 1.14.4（含 Wintun），由唯一 Windows 服务启动和管理；不需要目标机单独下载运行时。为了减少与教师端及学校局域网冲突，TUN 排除常见私有网段；系统管理员仍可停止进程或修改路由。教师端的设备列表显示最近心跳与 TUN 进程状态。

## 维护授权与恢复

授权请求在同一实际 TLS 连接核实学校证书后才发送密码，拒绝跳转 / 自动凭据 / 代理；证书错误、断网、错误密码或停用授权均不开始系统变更。无需重复登录教师后台，不将教师密码写入安装包、镜像、注册表或日志。`--password-stdin` 仅供受控自动化读取一行 UTF-8，不能把密码放到命令参数。

正常卸载要求该机器已向教师端登记，使用设备密钥与教师维护密码共同授权；设备撤销审批不会阻止卸载。故障 / 离线恢复时，提权 Windows 管理员可显式运行 `ohno-setup.exe --admin-recovery-remove`。此标准恢复通道不依赖教师端，不意味着能抵抗 OS 管理员绕过。应用列表卸载维护器自身可能需重启才能删除自身文件，程序会提示检查剩余目录。维护授权不等于已经实现自动升级，详见 [托管升级进展](../docs/managed-updates.md)。

## 源码中的受管升级布局

新的安装器在教师在线授权后才创建管理员/SYSTEM 可写、普通用户只读执行的程序目录，安装单一 SCM 服务和初始 `versions/0-<sha256>` 载荷，持久化 selector，再启动服务。固定宿主和恢复卸载入口不在自动覆盖范围；可替换 worker、请求 UI、TUN 载荷置于独立不可原地覆盖的版本目录。请求启动器读取 last-good 并验完整包；未提交的候选不会替换日常请求 UI。

教师先在本地 Web 端初始化发行信任，再下载学校专属安装器，才能将公开发行 key 固定在镜像中。旧版或没有发行 key 的通用安装不会自动接受服务端临时提供的 key；不会为了开启升级而共享教师密码或设备私钥。镜像克隆沿用硬件锚自动重建设备身份，日常策略与升级无需维护密码。

更新依次走签名/哈希/架构验证、完整暂存、在线设备授权、持久事务、真实 worker 健康提交；失败保留最后正常版本和高水位。服务通过 Windows 标准 recovery 恢复进程崩溃；报告的非崩溃失败恢复已配置，依微软文档在系统重启后生效，不保证新安装同次启动立即生效。明确 STOP/正常卸载不触发恢复。正常卸载仍要求教师维护密码；离线或状态损坏时，提升权限的 OS 管理员可用 `--admin-recovery-remove`。仅清理已标记版本目录中的固定文件，未知内容、重解析点与硬链接会保留供 IT 检查。

这些行为必须经该提交 Windows CI 的临时密钥/临时服务端验收；仍不代表已在目标精简 Windows 10/兆芯硬件或 OEM 教室镜像上通过实测，也不代表旧 alpha.6 下载包含此功能。
