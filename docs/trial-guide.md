# ohno 预发布隔离试用指南

**推荐安装流程：** 教师双击 `ohno-teacher.exe`，程序直接打开本机管理页 `http://127.0.0.1:8765`，无登录步骤。在页面点击“下载 Ohno-School-Setup.exe”。学校 IT 将这一**单文件安装包**复制至可恢复的 Windows 测试学生机，直接双击，允许 UAC，然后在教师端批准设备的 MAC 绑定。安装器会自动安装并启动服务，无需手工执行命令。只有学校专属包无需输入地址；公版 `ohno-setup.exe` 双击会显示服务器和证书选择窗口。

学校专属包携带的是教师端公开证书而非私钥。安装器会将教师自签证书加入学生机的整机受信任根；校方应当确认教师服务器及其证书可信，并在隔离环境先测试。教师电脑需允许 TCP 8443 入站，电脑名需在局域网正常解析；DHCP 不能替代稳定 DNS/主机名。教师程序关闭后服务端也会停止，尚未自动安装教师端 Windows 服务。

**下方命令行操作是 IT 调试路径，普通安装不需要。**

本指南描述预发布版的测试操作。先在可恢复的测试机上试验，不要分发到真实课堂。域名、IP 和路径均为示例，实际部署须替换。以下步骤能否完成以对应 Windows 自动化测试结果为准。

## 教师服务器

Windows x64 的 `ohno-teacher.exe` 为自包含程序，不需要安装 Python。将它放到权限受限的独立目录中，在该目录打开命令行：

```bat
ohno-teacher.exe --generate-certificate --host 192.168.1.10 --cert teacher-cert.pem --key teacher-key.pem
ohno-teacher.exe --state state.json --init
ohno-teacher.exe --state state.json --cert teacher-cert.pem --key teacher-key.pem --bind 0.0.0.0 --port 8443
```

教师端初始化不要求管理密码。教师端服务器若也使用 DHCP，应为其配置稳定的内网 DNS 名称（或 DHCP 地址保留），例如 `ohno-teacher.school.lan`；安装终端时用 HTTPS 域名而非猜测当前 IP。`--host` 必须与客户端访问的 IP 或域名一致。MAC 只用于识别终端，不负责发现服务器。`teacher-key.pem` 和 `state.json` 要通过 Windows 文件 ACL 限制为服务器管理员和服务账户可读写；`teacher-cert.pem` 是公钥，可分发给客户端。保护私钥，定期备份状态。启动命令目前需要人工运行或由学校 IT 通过自己的服务管理工具配置自启动。

## 学生端安装

将自包含的 `ohno-setup.exe` 和 `teacher-cert.pem` 放到测试机，运行：

```bat
ohno-setup.exe --install https://192.168.1.10:8443 --certificate teacher-cert.pem
```

安装器请求管理员权限，安装一个自动启动的 Windows 服务，并创建网站申请/教师解锁的公共桌面快捷方式。指定证书会把证书加入**整台电脑**的受信任根证书存储；事先应核对确为自己的教师服务器证书。卸载只移除安装器新增的证书。如果服务器证书已经受信任，可省略 `--certificate`。

在教师机打开 `http://127.0.0.1:8765/` 并批准对应设备；编辑规则后等待学生服务轮询。学生机不能通过 8443 访问教师管理页面。只能测试安装器明确支持且通过 Windows CI 的路径。卸载：

```bat
ohno-setup.exe --remove
```

卸载需管理员权限，并尝试恢复由 ohno 添加的 Edge 规则、证书和程序文件。确认没有残留再还原快照。

## DHCP、MAC 和设备身份

Ohno 不把 DHCP 分配的 IPv4/IPv6 地址当作设备身份。终端枚举网卡，优先读取驱动报告的物理网卡永久 MAC，有线优先于 Wi-Fi；存在多个网卡时按固定顺序选择主 MAC。教师端展示主 MAC、绑定 MAC 和最近连接 IP，后者仅供排障。

教师第一次批准设备时会绑定当前主 MAC；每次策略、解锁与审批均同时要求设备 ID 和独立密钥，且绑定 MAC 必须仍出现在上报的网卡列表里。同一 MAC 不会自动批准另一组设备凭据。网卡发生更换时必须由教师核验；出于镜像克隆安全考虑，终端主硬件锚变化也可能直接产生新设备 ID，需要重新批准。MAC 可伪造，拥有管理员权限的学生仍可绕过，不应把该功能当作强硬件证明。

请务必验证同型号机器的 SMBIOS UUID 和主 MAC 是否不同。真实联想教育机增量镜像最稳妥的方案是模板安装后在捕获前清理机器特有身份，再让每台机器首次启动生成凭据；当前软件只能尝试检测硬件变化并更换凭据。虚拟网卡、随机 Wi-Fi MAC 或驱动缺失可能影响结果，必须实测。

## 镜像分发前

模板机运行后会生成设备身份。当前实验实现检测 SMBIOS UUID 变化并更换设备凭据、清理缓存；必须验证至少两台目标机的 UUID 存在且互不相同，且教师端看到不同设备。还需验证联想镜像工具是否正确保留服务注册、程序目录、证书和规则，并验证还原/卸载。未验证前不要批量分发。

## 功能与限制

- 网站规则通过 TUN 按可识别的域名拦截，并通过受管理 Edge 的策略补充。TUN 排除常见私有网段、无法保证识别加密域名；不做透明 HTTPS 重定向。学生可通过桌面窗口输入域名申请，教师批准后对该设备限时添加精确域名例外。
- 默认游戏名单基于文件名，教师还可填写具体 SHA-256。进程被定期扫描并终止，存在执行前的时间窗口；Java 版 Minecraft、改名或其他启动器不保证识别。
- 可选的本地文件开关试图限制 Edge 的 `file://*` 导航，会同时影响本地 PDF、图片及课件；微软文档说明这一规则有局限，其他浏览器和网页内动态内容不保证覆盖。
- 对识别出下载标记或当前位于可移动磁盘的运行程序，试验性 WFP 规则拦截之后新建的出站连接；教师可限时批准。程序启动到扫描之间可能已经联网，标记和来源可能丢失，脚本与委托联网无法可靠归属，已有连接不会被保证切断。服务停止时动态规则会消失。**这不是杀毒软件，也不能保证阻止恶意程序联网。**
- 教师可以在学生机窗口输入可选的 4–8 位课堂 PIN 暂停一小时；默认关闭，服务器失联时不沿用临时放行。学生拥有管理员权限时可能记录 PIN，因此优先使用教师机本地管理页审批。
- 拥有本机管理员权限的学生可以结束服务或修改系统策略，SCM 的故障重启不能防止有意绕过。
