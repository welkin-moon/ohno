# ohno Windows 产品设计草案

## 目标和现实边界

目标是学校授权管理的 Windows 教室电脑，教师与学校 IT 有管理和恢复权限。当前已知学生账户有管理员权限；建议学校改成标准用户，否则无法保证学生不能停止服务或更改设置。保护运行、规则与设置时依靠 Windows 服务 ACL、受限目录和受管理的应用控制，不尝试声称能抵御本地管理员、离线修改系统、重装或物理攻击。保留显式卸载和恢复手段。

源文件的策略核心只是独立单元，不能拦截任何流量或进程。下列均为计划，并非已完成组件。

## 组件

1. **终端服务**：原生 Windows 服务，自启动，崩溃后由 SCM 按有限次数重启；状态变化和配置应用写事件日志。程序与策略存于仅管理员/SYSTEM 可写目录；标准用户不可停服务。交互 UI 与服务分进程，通过带 ACL 的命名管道通信。
2. **过滤执行层**：设计需按系统与签名条件确定。WFP 可提供系统级进程/连接决策；系统或供应商过滤驱动需经过签名、版本兼容、升级和卸载测试。TUN 负责将选定流量交给用户态处理，并不天然包含 HTTPS 的 URL/页面内容；开机顺序、路由回滚、IPv4/IPv6、系统代理、DNS/DoH、休眠唤醒和故障策略均需验证。不能声称只要启用 TUN 就完成所有功能。
3. **浏览器组件**：由受管理浏览器策略及扩展配合展示拦截和申请页面。HTTPS 透明重定向会引发证书域名不匹配；方案是由浏览器自身跳转至提示页面，不伪造站点证书，也不要求安装解密证书。应用须说明其它浏览器与程序的覆盖范围。Edge 的 URLBlocklist 有限制，不应假设 `file://*` 全面生效；本地 HTML 应通过经过测试的扩展、受控浏览器和必要的应用控制共同处理。
4. **应用控制**：优先评估 Windows App Control for Business 或 AppLocker 与学校现有管理兼容性，按发布者/文件哈希及进程上下文设计规则，并先审计再强制。游戏通常有多个不同版本、启动器或共享运行时（如 Minecraft 的 Java）；不对通用 `javaw.exe` 一刀切，需针对实际版本与启动参数等上下文验证。应用控制负责执行前阻止，不能依赖定时杀进程模拟真正的阻止。
5. **来源与联网**：下载来源标签（MOTW）与 U 盘所在卷仅是证据，并不能可靠追踪复制、解压、脚本、注入和进程委托后的来源。推荐以可信应用、受管理安装路径和已授权文件为正向信任基础：未证明可信则默认需要审批。WFP 中的程序/进程身份应结合创建时间、可信哈希、映像与文件替换检测；例如解释器下载脚本或浏览器载入网页的网络流量不能简单归属于某个文件。授权不能当作杀毒保障，仍需 Defender 等防护。
6. **教师端**：终端提交审批请求（设备、用户、类型、应用身份、目标、理由、创建时间），老师可批准一次或限定设备、用户、对象、用途和期限；拒绝和超时默认保持拒绝。管理端可编辑、预览、版本化发布和回滚网站及应用规则；变更须审计。认证、授信、通信加密及证书轮换需在设计时落地，不能只用明文共享密码。密码解锁可作为教师操作入口，但服务必须在受保护端验证，并限制尝试频率、提供恢复路径。
7. **学生提示**：受限时说明受限对象、原因、可向教师申请与状态，不暴露教师秘密；无教师端连接时显示离线状态及可恢复行为。

## 防复制镜像产生相同身份

安装包支持离线部署、静默安装和显式卸载；最终二进制随包携带依赖，目标机不需另行安装运行时。黄金镜像只安装程序及公开配置，**不在模板内生成可复制的设备私钥、长期令牌或设备 ID**。每台设备第一次启动时生成密钥，带学校管理者预先配置的一次性注册材料完成教师端注册；恢复、重装、设备报废时有吊销机制。策略签名密钥不放学生端，不将教师明文密码烧进镜像。验证 OEM 增量包是否保留服务注册、权限、驱动、证书、更新和卸载状态。

## 故障及恢复

- 发布规则前做语法、范围及冲突检查，支持灰度与自动回滚；不覆盖学校已有浏览器、网络或防火墙策略。
- 明确教师端失联、DNS 失效、过滤服务崩溃、驱动失效和误拦系统程序的处理，保留对教师端及恢复资源的可达性。
- 禁用/卸载应由教师或 IT 授权，完整恢复 ohno 创建的路由、代理、DNS、过滤规则及服务；不能破坏其它管理系统。
- 保留线下 IT 管理员恢复方案，学生不能操作；真实教室部署先在可还原的测试机试运行。
- 明确数据范围、留存期限和学校通知；只收集处理审批和管理所需数据，不记录网页内容、密码或无关私人文件。

## 最低验收（需要真实 Windows 设备）

1. 用 OEM 流程克隆至少两台电脑；首次启动后设备标识及私钥各不相同，均能注册和接收更新。
2. 标准用户无法停止服务或修改策略；授权教师可暂停、恢复和卸载；断电与异常退出后能恢复、不开机死循环。
3. 常用浏览器的 HTTP/HTTPS 被限制站点出现指定提示页并可申请；只对明确支持的浏览器和场景承诺。检查 IPv4/IPv6、DoH、重定向和代理。
4. 覆盖学校提供的实际游戏样本和不同路径/版本；网页 Minecraft 与本地 HTML 样本验证，正常教学页面、课件、允许的 Java 软件不中断。
5. 从浏览器、U 盘及复制、解压等路径测试未知程序的联网，以及单次/过期/拒绝/断网授权；审计落盘且无明文密码。
6. 升级、回滚、卸载、断网、重启和学校原有软件的互操作性通过测试。

## 实现里程碑

A. 定稿系统版本、学生权限、教师端拓扑和学校浏览器；收集真实样本并设计受限安装与恢复。
B. Windows 原生服务、安装/卸载、设备注册及教师认证，虚拟机做镜像分发试验。
C. 受管理浏览器扩展及提示/申请；应用控制审计模式验证实际名单。
D. 来源信任与联网执行层，审批与审计，处理离线和回滚；先小范围试运行，再逐步推广。
