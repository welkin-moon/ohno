# 已确认的目标环境和本轮决策

- 终端为兆芯 x64、Windows 10，系统可能精简；学生账户拥有管理员权限。
- 学生端用原生代码，随包静态链接第三方运行时；不要求安装 .NET 或 VC++ 再发行包。仍需 Windows 自身的 API 和必要服务。不能假设特定系统更新或组件一定存在。
- 手工安装时只出现一次 UAC；安装后由服务随 Windows 启动运行。随后用联想教育机增量镜像部署。具体镜像工具行为仍需实测。
- 教师端是内网服务器上的 Web 管理界面，统一调整网站/程序规则、接收和审批申请。内网也要身份认证和 HTTPS，不将管理密码或服务器私钥嵌入学生镜像。
- 优先不依赖浏览器扩展。网页访问受限时可使用弹窗提示或简单拒绝，不保证 HTTPS 任意网页透明跳转。无扩展无法可靠识别所有本地 HTML 内容或网页游戏，应明确覆盖范围，不能将域名/IP 屏蔽说成完整的网页内容识别。
- 管理员能修改服务、策略、权限和系统文件。自启动和 SCM 崩溃恢复有助于可靠运行，但不能承诺学生拥有完整管理员权限的同时完全防绕过。应向学校建议学生切为标准用户；若不能改变，教师端应提供设备心跳、服务异常提醒，并把检测解释为尽力而为。
- 优先探测 BFE/WFP 与现有防火墙能力，再确定联网限制。WFP 可支持部分用户态配置，但不能保证无驱动满足所有程序、文件来源及深度过滤需求。TUN 若需驱动，需提前评估签名与兼容性；不要先假设可以在精简系统安装。

## 接下来要做

1. 用 `windows/ohno-check.cmd` 在一台测试机获取版本及组件状态；确认学生是否真正可通过 UAC 获得提升后的管理员令牌。
2. 使用 Windows 构建环境、测试机和快照，验证原生服务/安装/卸载、SCM 恢复与镜像后首次启动；先不改网络。
3. 决定应用身份、无需扩展的网页控制及提示路径，明确功能覆盖和限制；建立小型 Windows 内网教师服务，完成鉴权与加密、设备注册、审批与规则更新。
4. 根据系统服务检测结果实现网络执行层，覆盖 IPv4、IPv6、DNS、异常退出与恢复；不能把文件来源标记视为完整的安全边界。
5. 单机验证后走联想工具增量分发，验证多个设备不同凭证、重启、故障和卸载。逐步在实际游戏和教学软件上测试。

- 最新决定：只运行一个 Windows 服务；不使用双进程互保。
