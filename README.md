# ohno

Windows x64 课堂助手：一个自启动服务、内网教师 Web 管理端和学生申请窗口。当前是开发预览，**尚未完成兆芯实机及联想镜像分发验证**，不应用于真实课堂的安全隔离。

## 直接双击安装（alpha.4）

教师机双击 `ohno-teacher.exe` 即可。程序同时启动两个完全分离的入口：

- `http://127.0.0.1:8765`：**只在教师机本地开放**的管理页，自动打开，**没有登录密码**。
- `https://<教师机>:8443`：只给学生端设备注册、策略同步和申请使用的局域网 API；这里没有教师管理页面。

教师在本地管理页下载本校专属 `Ohno-School-Setup.exe`，复制到学生模板机双击、允许一次 UAC，即自动安装并启动服务。设备随后出现在教师页，由教师批准 MAC 绑定。公版 `ohno-setup.exe` 双击也有原生 Windows 配置窗口，不需要终端命令。

“现场临时解锁”与后台权限彻底分开：教师页可选设置一个 4–8 位数字 PIN，只用于学生机现场暂停限制 1 小时；默认关闭。PIN 不参与教师管理，也不会明文保存。

教师机 TCP 8443 需允许学生网段访问，教师机名称需要在局域网稳定解析。管理口 8765 只监听 127.0.0.1，不应对 LAN 开放。该版本仍未在兆芯实机和联想 OEM 增量镜像流程现场验证，请先在可恢复测试机验证。

## 当前功能

- 自包含 Windows 安装器、单个自启动服务、SCM 异常恢复和卸载；无需另装 .NET 或 VC++ 运行库。
- 教师端自包含 Windows 程序；本机管理页仅监听 127.0.0.1:8765、无需登录，学生 API 独立监听 HTTPS 8443。首次启动自动生成 API 证书。
- 设备识别不依赖 DHCP IP：优先使用系统报告的物理有线网卡永久 MAC，结合 SMBIOS UUID 识别镜像克隆；教师批准时绑定 MAC。每台设备仍须使用独立凭据认证，MAC 本身不可作为密钥。
- 单个服务管理随包携带的 TUN 网络组件；教师端显示设备心跳和 TUN 进程状态。域名规则按可识别的域名拦截，Edge 浏览器策略补充阻止。
- 初始游戏文件名和网站名单可由教师编辑。按文件名/哈希监视程序并请求批准；学生可从桌面窗口申请网站解除，也可由教师使用可选的 4–8 位课堂 PIN 临时暂停本机规则。
- 实验性识别带下载区域标记、当前位于可移动磁盘的运行程序，通过 WFP 限制其新的 IPv4/IPv6 出站连接并向教师请求批准。
- 可选地限制 Edge 打开本地文件，可能影响本地 PDF/课件，且不能保证覆盖全部 HTML。

## 边界

学生拥有管理员权限时可以停止服务或修改系统设置。MAC 可被伪造，虚拟机和驱动可能缺少永久硬件 MAC；MAC 不可作为安全身份凭证。更换主要网卡、重新分发镜像或升级旧版时可能需要重新审批。程序监视有启动后的时间窗口，网站域名和文件来源可能无法识别。下载/U 盘程序的 WFP 规则在扫描后才创建，已建立的连接、复制后来源丢失、脚本与委托联网均不保证覆盖；**它不是防病毒功能**。TUN 排除常见私有网段，并不保证覆盖所有浏览器、加密域名或已有连接。课堂 PIN 在学生拥有管理员权限的机器上仍可能被读取，因此优先使用教师端本机审批；PIN 默认关闭。

在真实电脑分发前必须验证硬件 UUID 唯一性、驱动兼容、教学软件、路由和恢复、联想增量镜像、卸载以及故障情形。见 [隔离试用指南](docs/trial-guide.md)。

## 构建和测试

- `make test`：跨平台策略、JSON、SMBIOS 和 TUN 配置测试。
- `python -m pip install -r teacher/requirements.txt` 后执行 `python -m unittest discover -s teacher`：教师端测试。
- `.github/workflows/prototype.yml`：Windows x64 编译、进程和 WFP、Edge 策略、安装卸载及教师审批集成测试，打包自包含原型。构建时校验并嵌入固定版本的上游 TUN 组件；目标电脑不会下载运行时。

当前源码以仓库中的 AGPL-3.0 许可发布。上游 sing-box 与 Wintun 许可和来源见 `windows/` 中的许可证文件；安装包将随程序提供这些许可证。
